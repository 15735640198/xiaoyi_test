# HarmonyOS 设置项操作脚本生成 Prompt 输入指南

基于开发 `query_personal_hotspot_state.py`（个人热点开关查询）和 `bluetooth_manager.py`（蓝牙设备管理）两个脚本的实际经验，总结后续用 prompt 生成指定功能脚本时需要提供的必要输入。

## 一、必须提供的信息

| 信息项 | 说明 | 示例 | 不提供会怎样 |
|--------|------|------|-------------|
| **功能描述** | 脚本要做什么 | "查询个人热点开关状态" / "连接/断开/查询蓝牙设备" | 无法确定脚本目标 |
| **操作模式** | 支持哪些操作 | connect / disconnect / query | 无法设计参数和分支逻辑 |
| **入参定义** | 参数名和含义 | `--mode`, `--Bluetooth_name` | 无法设计命令行接口 |
| **导航路径** | 从哪个应用入口到目标页面 | "设置 > 星闪和蓝牙" 或 "设置 > 移动网络 > 个人热点" | 需要逐步 dump 调试每一层入口文本，最耗时 |
| **目标控件类型** | 要操作的是什么 | Toggle开关 / 设备名称文本 / Slider滑块 / 按钮 | 无法确定状态读取方式 |

## 二、强烈建议提供的信息（能大幅减少调试）

| 信息项 | 说明 | 示例 | 影响 |
|--------|------|------|------|
| **入口文本** | 每一层菜单的实际显示文字 | "星闪和蓝牙"（不是"蓝牙"） | 文本不匹配 → `find_by_text` 找不到 → 脚本卡住 |
| **状态显示方式** | 目标状态在 UI 上怎么呈现 | 开关：Toggle 的 `checked` 属性；蓝牙连接：设备名旁边有"已连接"文本 | 无法设计状态判断逻辑 |
| **弹窗/对话框** | 操作过程中会出现什么弹窗 | "配对新设备时会弹出配对确认框，有'配对'和'取消'按钮" | 不提供 → 脚本不知道要处理弹窗 → 操作失败 |
| **设备列表结构** | 设备在哪个区域 | "已配对设备"和"其他设备"两个分区 | 无法区分已配对/未配对设备 |

## 三、有帮助但可以自动发现的信息

| 信息项 | 说明 | 发现方式 |
|--------|------|----------|
| 应用包名/Ability | `com.huawei.hmos.settings` / `MainAbility` | `hdc shell bm dump -a` 自动查 |
| hdc 路径 | DevEco Studio SDK 下的 hdc.exe | 脚本自动搜索常见路径 |
| 控件树 JSON 结构 | 属性嵌套在 `attributes` 字典里 | `uitest dumpLayout` 后分析 |
| bounds 坐标格式 | `[left,top][right,bottom]` | dumpLayout 输出中可见 |
| 组件是否可点击 | Text `clickable=false`，Row `clickable=true` | dumpLayout 分析 |

## 四、理想 Prompt 模板

以最精简的方式提供以上信息，一个理想的 prompt 应该是这样的：

```
帮我写一个 [功能描述] 的脚本。

导航路径：设置 > [第一层菜单] > [第二层菜单]
入口文本：[每一层的实际显示文字，如"星闪和蓝牙" > "个人热点"]

操作模式：[connect / disconnect / query]
入参：[--mode=xxx, --name=xxx]

目标控件：
- 控件类型：[Toggle开关 / 文本 / Slider滑块]
- 状态判断方式：[checked属性 / 旁边的"已连接"文本 / value值]

弹窗处理：
- [操作]时会弹出 [弹窗描述]，需要点击 [按钮文本]

设备环境：
- hdc 已安装，在 PATH 中
- 设备已通过 USB 连接
- 系统语言：中文
```

## 五、用两个实际脚本对比

| 信息项 | 个人热点脚本 | 蓝牙管理脚本 |
|--------|------------|------------|
| 功能 | 查询开关状态 | 连接/断开/查询设备 |
| 导航路径 | 设置 > 移动网络 > 个人热点 | 设置 > 星闪和蓝牙 |
| 入口文本 | "移动网络" → "个人热点" | "星闪和蓝牙"（**不是**"蓝牙"） |
| 目标控件 | Toggle，读 `checked` | 设备名旁边的"已连接"文本 |
| 弹窗 | 无 | 配对弹窗，需点"配对"（**不是**"已配对设备"标题） |
| 额外难点 | 无 | 设备名 Text 不可点击，需点父级 Row；列表需滚动查找；设备扫描需等待 |

## 六、核心结论

**调试时间最长的 3 个问题，都是因为 prompt 缺少信息导致的：**

1. **入口文本不精确**："蓝牙" vs "星闪和蓝牙" → 如果 prompt 里写明实际显示文字，可以省掉所有导航调试
2. **弹窗信息缺失**：不知道配对弹窗的存在 → 如果 prompt 提前说明"会弹配对确认框，有配对/取消按钮"，脚本初版就能处理
3. **状态判断方式不明**：不知道蓝牙连接状态靠"已连接"文本来判断 → 如果 prompt 说明状态如何显示，可以一次写对

**一句话总结：提供「导航路径每一层的实际文字」+「弹窗有哪些按钮」+「状态在 UI 上怎么显示」，脚本基本能一次写对。**
